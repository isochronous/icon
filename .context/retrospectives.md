### ICON-0096: A requirement that reality contradicts is a requirement to change
- **Avoid**: Two failures, both of overweighting the wrong half of a task. First, the detection was treated as the hard part and given an architecture-shaped investigation — a manufactured PowerShell-twin policy conflict included — when the maintainer's one-line answer was `node -v`, a single command identical in both shells. The reflex to assume a cross-platform primitive needs a twin invented a conflict that never existed. Second, and more costly if it had shipped: the obvious detector keys on exit status, and **PowerShell does not update `$LASTEXITCODE` on `CommandNotFoundException`** — measured on 7.6.3 and 5.1, a missing binary leaves the prior value in place, so `if ($LASTEXITCODE -ne 0)` reports "present" in exactly the case the skill exists to catch. bash returns 127 and cmd 9009; only PowerShell is silent. The failure is directional — with the binary present the variable updates correctly — so it is a pure fail-open, never a false negative, which is precisely why testing only the happy path would have missed it.
- **Repeat**: Three things. (1) **When a requirement conflicts with reality, change the requirement.** A `SessionStart` hook cannot report its own non-execution — the harness synthesizes the error about a file it never read, so no code inside that file can make its absence louder. Rather than approximate "make the hook's failure visible" with something weaker wearing the same words, the issue was amended and detection moved to paths that actually execute. (2) **Pre-commit the disposition before the evidence arrives.** A table of "if investigation finds X, do Y" was written into plan.md *before* the test ran, so the answer picked the branch instead of convenience picking it. (3) **A detector's failure direction matters more than its accuracy.** The string-matching replacement was attacked with a directory named `node`, a broken shim, an empty-output shim and locale variation; every failure degrades toward "absent", never toward a false "present". A check that fails toward "problem" is worth more than one that is right more often but fails toward "fine".
- **Updated**: `.context/standards/shell-portability.md` § Testing Pattern — added a fourth shape of the PowerShell fail-open family (ICON-0096): `$LASTEXITCODE` is not updated when PowerShell cannot resolve a command, so an exit-status guard reports "present" in the absent case; test command existence via output, not exit status.

### ICON-0094: The failure path adjacent to the fix
- **Avoid**: Five review rounds, each finding real defects, and after round 1 every Critical was the *same shape in a new place* — the fix hardened the path it was aimed at and left the failure path beside it unguarded. The reviewer's round-4 sentence is the durable form: *each round fixed the happy path it was aimed at and left the failure path adjacent to it unguarded.* When fixing a fail-quiet defect, the fix is not "make the success path correct" — it is "read every handler, `else`, and refusal path as its own control flow and ask what prints if *this block* fails." When that sweep finally ran, it found four more fail-opens, two of them in code the task had never touched. ### ICON-0093: A portability fix that is read rather than run is a hypothesis
- **Avoid**: Three consecutive rounds shipped a portability fix that had never been executed, and each was wrong in a way reading could not reveal. The investigation sweep explicitly cleared `mktemp` as a false positive after checking the *flag* and never checking the *template shape* — `.retro_tmp_XXXXXX.md` has its `X`s mid-string, which BSD `_gettemp` silently substitutes zero of, so the first remediation traded a loud macOS failure (`illegal option -- p`) for a silent one (a literal file named `.retro_tmp_XXXXXX.md`, exit 0, uniqueness gone). That remediation then introduced a CDPATH regression by replacing `realpath` with an unguarded `cd`, and the next one introduced a fail-open `|| rm -f` that returns 0 when the `sed` it guards fails. Every one of these was caught by *running* the construct and none by reading it. Two compounding traps: a portability fix can move a failure from loud to silent, which looks like success under Linux CI plus one manual macOS test; and a sweep's own report that it was exhaustive is not evidence — this task's `plan.md` asserted "every live violation is fixed" while two remained.
- **Repeat**: Two things. (1) **Classify before substituting.** `grep -oP` had three distinct fix shapes depending on what the pattern used — no PCRE feature (clean flag swap), a shorthand like `\d` (swap plus translation, because in ERE `[\d.]` silently becomes the set `{\, d, .}`), or `\K` (no ERE equivalent exists; the extraction must move to `sed`). A uniform flag sweep would have silently broken version extraction. Writing that triage into `plan.md` *before* dispatching is what kept four sites from collapsing into one wrong pattern. (2) **Brief each re-review to assume the previous remediation introduced a regression.** Rounds 2 and 3 were told exactly that, and each found one. Framing a re-review as confirmation finds nothing; framing it as adversarial found a defect every time.
- **Updated**: `.context/standards/shell-portability.md` § Testing Pattern — added two companion paragraphs plus a BROKEN/correct `mktemp` fence: (1) the procedure applies to a corrected fix and to any idiom this document prescribes for others to copy, not just the code being replaced — Rule 8's own cleanup fence was fail-open for a full review round, caught only when a reviewer copied it out of the document and ran it; (2) a portability fix can trade a loud failure for a silent one on a different platform, worked via the `mktemp -p` case (loud `illegal option -- p` on macOS <=13.x vs. the silent fixed-filename collision on macOS 14+/FreeBSD 13.2+).
