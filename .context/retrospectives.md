### ICON-0093: A portability fix that is read rather than run is a hypothesis
- **Avoid**: Three consecutive rounds shipped a portability fix that had never been executed, and each was wrong in a way reading could not reveal. The investigation sweep explicitly cleared `mktemp` as a false positive after checking the *flag* and never checking the *template shape* — `.retro_tmp_XXXXXX.md` has its `X`s mid-string, which BSD `_gettemp` silently substitutes zero of, so the first remediation traded a loud macOS failure (`illegal option -- p`) for a silent one (a literal file named `.retro_tmp_XXXXXX.md`, exit 0, uniqueness gone). Every one of these was caught by *running* the construct and none by reading it. Two compounding traps: a portability fix can move a failure from loud to silent, which looks like success under Linux CI plus one manual macOS test; and a sweep's own report that it was exhaustive is not evidence — this task's `plan.md` asserted "every live violation is fixed" while two remained.

(2) **Brief each re-review to assume the previous remediation introduced a regression.** Rounds 2 and 3 were told exactly that, and each found one. Framing a re-review as confirmation finds nothing; framing it as adversarial found a defect every time.

### ICON-0092: Removing a skill instead of repairing it
- **Avoid**: The `ecological-impact` skill shipped a worked example that disagreed with its own formulas by 1000×, was internally inconsistent on its own units, and quoted a headline rate ~57× the source it cited — and **four consecutive audits read that block without checking the arithmetic**. Prose gets read for shape; numbers embedded in prose get skimmed. A document that asserts computed values nothing in the repo can re-derive has no mechanism by which anyone would notice it is wrong, so the error survives every review indefinitely. When a shipped artifact carries numbers, either make them re-derivable from something committed or expect them to rot unnoticed.
- **Repeat**: Two things. (1) **Removal was cheaper than repair, and choosing it was correct** — the skill was a novelty whose entire value depended on numbers no one could verify, so repairing it would have bought a maintenance obligation for the same unverifiable claims. When triaging a defect, ask what the artifact is worth before asking what the fix costs. (2) Writing the *exclusion reasoning* into `plan.md` Decisions **before** the work — which historical references to leave, and why editing `context_template/` would force a schema bump for a no-op — let the reviewer verify each exclusion against the tree instead of re-deriving the judgement. The reviewer reported no daylight between the claimed and actual state. Recording why something was deliberately *not* touched is as useful to a reviewer as recording what was.
- **Updated**: `.claude/skills/icon-audit/SKILL.md` § Quality Checklist — added a bullet requiring any numeric or computed claim in audited content (worked example, formula, headline rate, cited statistic) to be independently recomputed and checked against its cited source, not read for shape, citing ICON-0092. Judged a distinct axis from the two adjacent lessons: `verify-design-claims-against-artifacts.md` covers a design's claim about gate/hook/config *behavior*, verified before dispatch — verification there is cheap and singular; this lesson is about a *content* claim (an arithmetic/numeric assertion) that resists detection entirely because nothing prompts a reader to check it, unlike ICON-0091's "resisted repeated correction" pattern (multiple passes tried and failed) — here no pass ever tried, across four audits. Promoted to `icon-audit`'s Quality Checklist rather than `.context/standards/` because the concrete failure was audit coverage (four consecutive audits missed it) and the concrete fix is an audit-time check; `icon-audit`'s `## Common Check Patterns` list (the earlier-catching alternative) is duplicated verbatim across all 6 domain briefs, so editing it would mean 6 files — over the one-promotion-target scope for this task. `verify-design-claims-against-artifacts.md` left untouched at 14,999 bytes (not this lesson's axis).

### ICON-0091: Amending a decision record that had gone stale
- **Avoid**: The correction reproduced the defect it was correcting, twice. Round 1 added a *new* false assertion to ADR-005's Decision with a fabricated `(ADR-004)` citation — ADR-004 contains no shell, no parity, no `.ps1`. Round 2's replacement enumerations were incomplete again. Round 3's caveat sentence, written specifically to stop undercounts, contained one. The count of unpaired shell scripts was stated four times and wrong four times (6, 7, 8, against an independently rebuilt 9), and one file — `context_template/context/workflows/post-commit` — evaded five passes, three of which explicitly verified "against the repo." The cause was not carelessness: **"the set of committed scripts" has no reliable representation** — extension misses the extensionless git hooks, a shebang grep matches a markdown file containing fenced shebangs, directory membership misses the `context_template/` copies. When a fact resists repeated careful correction, suspect it is not representable rather than that the last reader was sloppy, and **remove the claim instead of correcting it**. A document should state where things live, not inventory what exists.
- **Repeat**: Three things carried this. (1) Instructing every agent to **rebuild the evidence itself rather than inherit the numbers from its brief** — that is what surfaced that the manager's count was wrong, then that the fix's count was wrong, then that the reviewer's was too. A brief is a lead, not a fact, and saying so in the dispatch is what makes an agent check. (2) Three review rounds, each catching a real defect the previous round introduced, plus one fix agent that caught an error in its own draft before staging — a review that returns "changes requested" twice is working, not failing. (3) When the new `## Amendments` format rule turned out to be violated by two of its own three examples, **the rule was relaxed to match what three independent authors actually wrote**, rather than reformatting the documents to match the rule. A convention whose first uses violate it is the wrong convention.

Judged a genuinely distinct axis rather than a same-file addition: the existing file's remedy is "verify the claim before relying on it" (verification is possible, merely skipped); this lesson is "verification was attempted repeatedly and still failed, because the claim had no representation to verify against" — the remedy is removing the assertion, not verifying harder.
